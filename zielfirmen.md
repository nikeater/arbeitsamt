# Technischer Teil: RSS und Job-Feeds

## Das Grundproblem
Klassische RSS-Feeds bieten die wenigsten Karriereseiten an. Was es dafür fast überall gibt,
sind **öffentliche JSON- oder XML-Endpunkte der Bewerbermanagementsysteme** — dieselben Daten,
die die Karriereseite selbst lädt. Die kannst du abfragen und dir selbst in RSS umwandeln.

## Endpunkte nach System

| System | Endpunkt | Format |
|---|---|---|
| Personio | `https://{firma}.jobs.personio.de/xml` | XML |
| Greenhouse | `https://boards-api.greenhouse.io/v1/boards/{token}/jobs?content=true` | JSON |
| Lever | `https://api.lever.co/v0/postings/{slug}?mode=json` | JSON |
| Ashby | `https://api.ashbyhq.com/posting-api/job-board/{name}` | JSON |
| SmartRecruiters | `https://api.smartrecruiters.com/v1/companies/{id}/postings` | JSON |
| Workable | `https://apply.workable.com/api/v1/widget/accounts/{account}` | JSON |
| Recruitee | `https://{firma}.recruitee.com/api/offers/` | JSON |
| BambooHR | `https://{firma}.bamboohr.com/careers/list` | JSON |

**Für deine Liste am wichtigsten: Personio.** Das ist im deutschen Mittelstand der Standard —
also bei den meisten InsurTechs, Beratungen unter 500 Mitarbeitern und Softwarehäusern auf
deiner A-Liste. Und es liefert bereits XML, das du fast unverändert als Feed nutzen kannst.

## Welches System nutzt eine Firma?
Karriereseite öffnen und auf die URL schauen, auf die der Bewerben-Button zeigt. Alternativ im
Seitenquelltext nach `personio`, `greenhouse`, `lever`, `ashby`, `smartrecruiters`, `workable`,
`recruitee` suchen. Der Firmen-Slug steht in der URL.

## Konzerne
Große Häuser (Allianz, ERGO, Munich Re, Deloitte, Bundesbehörden) laufen meist auf SAP
SuccessFactors, Workday oder Oracle. Die haben keine offenen Endpunkte. Dort bleiben drei Wege:
Job-Alerts der Karriereseite abonnieren, die Seite selbst per Skript beobachten, oder die
Konzerne über einen Aggregator abdecken und nur die Mittelständler selbst feeden.

## Vorschlag für den Aufbau
1. Für jede Firma auf der A-Liste System und Slug ermitteln, in eine YAML- oder JSON-Datei.
2. Ein Python-Skript, das alle Endpunkte abfragt und in ein einheitliches Schema normalisiert.
3. Filter auf deine Suchbegriffe (Analyst, Consultant, Data, KI, Prozess, Automatisierung).
4. Ausgabe als RSS-Datei plus Diff gegen den letzten Lauf, damit du nur Neues siehst.
5. Per Cron einmal täglich.

Schritt 2 bis 4 ist eine überschaubare Menge Code und ein gutes zweites Repository für dein
GitHub-Profil — sichtbar nützlich, klar dokumentierbar und thematisch passend zu allem, was du
gerade bewirbst.
